## Проверки и границы

- Прочитаны отличия от зафиксированной R1 в архитектуре, двух ADR, дорожной карте, реестре, M05/M06/M11/M25/M27/M28/M30/M34/M35/M37/M38 и затронутых задачах решений и последующих поставок. Проверены сценарии, где отзыв видимости опубликованного поля влияет на перенесённый черновик и его печать, поздняя доставка и ручная цель, восстановление старого напоминания с дедлайном A после изменения на B, а также запрет выдачи при неполной контрольной последовательности.
- Эталонами остаются 13-страничный PDF ИТМО и дерево main `b8cb42f812b695292afb2558bca26c2a2c162043`. Матрица требований, исходные заключения двух архитекторов и снимок GitHub совпадают с проверенными в R1. Подтверждены 52 отдельных требования и 19 разночтений. Сопоставления §6 на 12 строк и §7 на 11 шагов сохранены. Все 52 обратных связи требования с задачами в Markdown сверены с JSON. Согласование ИТМО вынесено в задачи решений, отдельное действие по допуску пилота — в M37.
- Python-проверка всех 64 ключей нашла ациклический граф без отсутствующих предшественников. Из M37 достижимы все остальные 46 задач пилота, из F-OPS — обязательные последующие пакеты. Сверены три независимых стартовых задания и предпосылки M38, M35, M37, F-AN. В полном объёме после двух пилотных подключений остаются четыре внутренних и девять внешних источников; при 3–5 чел.-дн. на каждый сумма F-15 составляет 39–65. Сумма обязательных пакетов после P0 составляет 95–173 чел.-дн.
- Ресурсное расписание рассчитано независимо по оценкам JSON. Для пилота получены 75/98,5/122 чел.-дн., критические цепочки 31/40/49 рабочих дней, расчёт с ожиданиями — 33/43/53 дня для трёх и 32/41,5/51 для четырёх. У M15/M16/M17 одинаковая оставшаяся длина цепочки. Допустимый выбор M17, затем M16, затем M15 воспроизводит опубликованные интервалы двух коннекторов. В средней модели M34 завершается в день 29,5, M27 — в день 35,5, M38 — в день 38. Последующая M35 принимает на одной сборке восстановление, срок хранения и работу настоящего обработчика; проверка на раннем M34 сама по себе этот результат не даёт.
- Заключение касается проекта системы. Функциональная, нагрузочная и пользовательская приёмка остаются задачами разработки. Для пилотных данных нужны решения ИТМО, для назначения срока — реальные доступы и фактическая скорость команды. Прикладное приложение не запускалось.
